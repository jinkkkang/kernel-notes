# 10.8 OOM

**结论**：慢路径里回收和压缩都没能拿出页，`__alloc_pages_may_oom` 调用 `out_of_memory`。选谁死看 `oom_badness`：文件页、匿名页、shmem、swap 项、页表页，再按 `oom_score_adj` 平移。被选中的进程要跑完退出才还得出页；`TIF_MEMDIE` 让它的退出路径能用保留内存。OOM 打印之后空闲页不会立刻出现。

> `mm/oom_kill.c`。分配侧入口在 [03-06-slowpath.md](./03-06-slowpath.md)。
> 过量分配的三种策略在 `Documentation/mm/overcommit-accounting.rst`，检查函数是 `mm/util.c` 的 `__vm_enough_memory`。
> MGLRU 的 `min_ttl` 也会从 kswapd 进 `out_of_memory`，见 [05](./10-05-mglru-code-path.md)。
> 导航：[上一篇 swap](./10-07-swap-zswap.md) · [本目录](./10-00-reclaim.md) · [下一篇 mlock](./10-09-mlock-unevictable.md)

本树的 `Documentation/mm/oom.rst` 只有标题。下面的选择和杀死流程以 `mm/oom_kill.c` 为准。

## 谁进来

```text
__alloc_pages_may_oom                     # page_alloc.c:3322
  out_of_memory                           # oom_kill.c:1113
    oom_killer_disabled：返回 false
    通知链交出了页，且不是 sysrq：返回 true
    task_will_free_mem(current)：mark_oom_victim，排队 oom reaper，返回
    没有 __GFP_FS 且不是 memcg OOM：返回 true   # 注释：不补偿不能做 IO 的回收
    constrained_alloc                     # :253，算 totalpages 和约束类型
    check_panic_on_oom                    # :1069
    sysctl_oom_kill_allocating_task 且 current 可杀：
      直接选 current
    否则 select_bad_process               # :366
      oom_evaluate_task                   # :310
        oom_badness                     # :203
    oom_kill_process                      # :1020
      __oom_kill_process                  # :924
        SIGKILL，mark_oom_victim，排队 reaper
```

`mark_oom_victim`（`:763`）把 `TIF_MEMDIE` 设上（`:770`）。已经设过就返回。注释写：被冻住的任务要解冻，否则 OOM 杀了也还不了内存。`exit_oom_victim`（`:793`）清掉这个标志。

## `oom_badness`（`:203`）

返回 `LONG_MIN` 的进程不参与选择：`oom_unkillable_task`、`find_lock_task_mm` 失败、`oom_score_adj == OOM_SCORE_ADJ_MIN`、mm 已标 `MMF_OOM_SKIP`、或正在 `in_vfork`。

剩下的分数：

```c
points = get_mm_rss(p->mm)
       + get_mm_counter(p->mm, MM_SWAPENTS)
       + mm_pgtables_bytes(p->mm) / PAGE_SIZE;
adj = (long)p->signal->oom_score_adj;
adj *= totalpages / 1000;          /* 把 -1000..1000 摊到总页数上 */
points += adj;
```

`get_mm_rss`（`include/linux/mm.h:2663`）是文件页 + 匿名页 + shmem。注释（`:229-230`）写基线是 rss、页表和 swap 占用的比例。

`oom_score_adj` 为 0 时，分数就是这三笔账。调到 `OOM_SCORE_ADJ_MIN` 直接排除，调高则在同样占用下更先被选中。`/proc/<pid>/oom_score_adj` 写的就是这个字段。

`totalpages` 由 `constrained_alloc`（`:253`）按约束算：

| 约束 | `totalpages` |
|---|---|
| memcg OOM | `mem_cgroup_get_max`，至少 1 |
| 没开 NUMA，或没有 zonelist，或 `__GFP_THISNODE` | `totalram_pages() + total_swap_pages`，约束记成 `CONSTRAINT_NONE` |
| mempolicy 把节点集缩小了 | 允许节点的 present 页 + `total_swap_pages` |
| cpuset 挡住了某些 zone | cpuset 允许节点的 present 页 + `total_swap_pages` |
| 都不是 | `totalram_pages() + total_swap_pages` |

`select_bad_process`（`:366`）取得分最高的。已经是 OOM 受害者且还没 `MMF_OOM_SKIP` 的任务会中止这次选择（`oom_evaluate_task`，`:328-331`），避免再给别人保留内存。`oom_task_origin` 的任务直接 `LONG_MAX`。

## 杀死之后

`__oom_kill_process` 先计 `OOM_KILL`，再向整个线程组发 `SIGKILL`，然后 `mark_oom_victim`。共享同一个 mm 的其它进程也会收到 `SIGKILL`，但注释写它们拿不到保留内存，避免把保留内存耗光。init 钉住这个 mm 时设 `MMF_OOM_SKIP`，reaper 不去收。

`oom_kill_process` 在动手前看 victim 是不是已经要退出：是的话只 `mark_oom_victim` 并排队 reaper。否则打 header，看 `memory.oom.group`（`mem_cgroup_get_oom_group`），先杀选中的任务，再按组扫。

OOM 之后不一定立刻有空闲页。被杀进程要跑退出、拆 VMA、还 folio。`dmesg` 里的 `Killed process` 是 `__oom_kill_process`（`:957`）打的。

memcg 的 OOM 是另一条：charge 撞上 `memory.max` 且回收失败。事件在 `memory.events` 的 `oom` / `oom_kill`。`out_of_memory` 对 memcg 约束打的消息是 `Memory cgroup out of memory`（`:1179-1180`）。不要把全局 `oom_kill` 计数当成某个容器的 OOM。在 6.12 上采样，这台机器的 `oom_kill` 是 0。

kswapd 在 MGLRU `min_ttl` 保不住时也会进 `out_of_memory`，见 [05](./10-05-mglru-code-path.md)。

## sysctl

都在 `mm/oom_kill.c` 的 `vm_oom_kill_table`（`:710`），名字挂在 `vm.` 下面。

| 名字 | 行为 |
|---|---|
| `vm.panic_on_oom` | 0 到 2（`extra2` 是 `SYSCTL_TWO`）。0 不 panic。1 只在 `CONSTRAINT_NONE` 时 panic，cpuset / mempolicy / memcg 失败不 panic。2 一律 panic。sysrq 触发的不 panic（`:1071-1087`） |
| `vm.oom_kill_allocating_task` | 非 0 时，全局 OOM 优先杀当前分配者，只要它有 mm、可杀、cpuset 允许、`oom_score_adj` 不是最小值（`:1155-1162`） |
| `vm.oom_dump_tasks` | 同一张表里的第三个旋钮，控制要不要把任务表打出来 |

`vm.overcommit_memory` 在 `kernel/sysctl.c:2060`，默认 `OVERCOMMIT_GUESS`（`mm/util.c:830`）。三个值在 `include/uapi/linux/mman.h:13-15`，文档 `Documentation/mm/overcommit-accounting.rst`：

| 值 | 宏 | 文档里的意思 | `__vm_enough_memory`（`util.c:958`） |
|---|---|---|---|
| 0 | `OVERCOMMIT_GUESS` | 启发式。明显过头的地址空间拒绝。默认 | `pages > totalram_pages() + total_swap_pages` 则失败 |
| 1 | `OVERCOMMIT_ALWAYS` | 总是允许过量分配 | 直接返回 0 |
| 2 | `OVERCOMMIT_NEVER` | 提交量不得超过 swap 加上可配置的物理内存（默认 50%） | 用 `vm_commit_limit()`。非特权再扣 `sysctl_admin_reserve_kbytes`。`vm.overcommit_ratio` / `vm.overcommit_kbytes` 只在这个模式起作用 |
