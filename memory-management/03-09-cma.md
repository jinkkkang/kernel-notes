# 3.9 CMA

**结论**：CMA 在启动时划出一段物理连续的页，平时借给可移动分配用，设备要大块连续内存时再把借用者迁走、把这段还回来。它解决的是「平时不能闲置一大块，驱动偶尔却要连续物理页」。

> 区描述在 `mm/cma.h`。对外函数在 `include/linux/cma.h`。分配在 `mm/cma.c`。
> 内核版本：**v6.6.160**。
> 导航：[上一篇 NUMA](./03-08-numa-policy.md) · [本目录](./03-00-page-alloc.md) · [下一节 SLUB](./04-slab.md)

一块 `struct cma` 是一段连续的 PFN：`base_pfn` 加上 `count` 页。全局有多块这样的区，放在 `cma_areas[MAX_CMA_AREAS]`（`mm/cma.c:39`）。`MAX_CMA_AREAS` 在编了 `CONFIG_CMA_AREAS` 时是 `1 + CONFIG_CMA_AREAS`（`include/linux/cma.h:13-15`），多出来的 1 是全局默认区。

对齐不能小于一个 pageblock：`CMA_MIN_ALIGNMENT_PAGES` 就是 `pageblock_nr_pages`（`include/linux/cma.h:24`）。

## `struct cma_kobject`（`mm/cma.h:8`）

```c
struct cma_kobject {
	struct kobject kobj;	/* 挂到 sysfs 的 kobject */
	struct cma *cma;	/* 回指这一块 CMA 区 */
};
```

## `struct cma`（`mm/cma.h:13`）

```c
struct cma {
	unsigned long base_pfn;		/* 这段连续页的起始 PFN */
	unsigned long count;		/* 有多少页 */
	unsigned long *bitmap;		/* 分配位图。1 bit 代表 1 << order_per_bit 页 */
	unsigned int order_per_bit;	/* 位图里 1 bit 对应的页阶 */
	spinlock_t lock;		/* 保护位图 */
#ifdef CONFIG_CMA_DEBUGFS
	struct hlist_head mem_head;		/* debugfs 跟踪的已分配块 */
	spinlock_t mem_head_lock;		/* 保护 mem_head */
	struct debugfs_u32_array dfs_bitmap;	/* 把位图露到 debugfs */
#endif
	char name[CMA_MAX_NAME];	/* 区名。CMA_MAX_NAME 是 64（include/linux/cma.h:17） */
#ifdef CONFIG_CMA_SYSFS
	atomic64_t nr_pages_succeeded;	/* 成功页数 */
	atomic64_t nr_pages_failed;	/* 失败页数 */
	struct cma_kobject *cma_kobj;	/* sysfs 对象 */
#endif
	bool reserve_pages_on_error;	/* 迁移失败时要不要把页留在保留状态 */
};
```

位图的长度是 `count >> order_per_bit`（`cma_bitmap_maxno`，`mm/cma.h:39`）。

```text
cma_alloc(cma, count, align, no_warn)          # mm/cma.c:425
  cma 为空、count 为 0、或者 bitmap 还没建：失败
  bitmap_count = 把 count 换成位数
  位数比整个位图还大：失败
  循环：
    拿 cma->lock
    bitmap_find_next_zero_area_off            # 按 align 找一段空位
    找到就把这些位置 1，放下 cma->lock
    pfn = base_pfn + (bitmap_no << order_per_bit)
    拿全局 cma_mutex（cma.c:41）
    alloc_contig_range(pfn, pfn + count,
                       MIGRATE_CMA,
                       GFP_KERNEL | (no_warn ? __GFP_NOWARN : 0))
                                             # page_alloc.c:6198
    成功：pfn_to_page，跳出
    失败：cma_clear_bitmap
    ret == -EBUSY：换一个起点再找
    其它错误：停
  成功的页逐页 page_kasan_tag_reset
  成功：count_vm_event(CMA_ALLOC_SUCCESS)，sysfs 加上 count
  失败且 !no_warn：pr_err_ratelimited，并 cma_debug_show_areas
       count_vm_event(CMA_ALLOC_FAIL)

cma_release(cma, pages, count)                 # :556
  cma_pages_valid：pfn 必须落在 [base_pfn, base_pfn + count)
  free_contig_range(pfn, count)                # page_alloc.c:6423
  cma_clear_bitmap
```

`alloc_contig_range` 才是「把借用者迁走」的地方。它把这段 PFN 隔离出来，迁走上面的可移动页，再从 buddy 里拿出来交给 CMA。`cma_alloc` 返回的 `struct page *` 就是这段的第一页，引用计数由 `alloc_contig_range` 立好。`no_warn` 为真时给这次迁移用的 gfp 加上 `__GFP_NOWARN`，失败日志也不打。

全局 `cma_mutex` 把各次 `alloc_contig_range` 串起来。位图自己的 `cma->lock` 只在找空位和改位的那一小段里拿着，注释（`:466-468`）写明：位已经置上，锁可以放下；迁移失败再拿回来清位。

`cma_declare_contiguous_nid`（声明 `include/linux/cma.h:34`）在启动时登记一块区，可以指定 node。`cma_declare_contiguous`（`:39`）是它的包装，nid 传 `NUMA_NO_NODE`。`cma_init_reserved_mem`（`:47`）把已经预留的物理范围接成 CMA。`cma_reserve_pages_on_error`（`:58`）把 `reserve_pages_on_error` 置上。

buddy 侧：可移动分配带 `ALLOC_CMA`。`__rmqueue` 在 CMA 空闲页超过这个 zone 空闲页的一半时，会先从 `MIGRATE_CMA` 拿（[04](./03-04-pcp-and-rmqueue.md)）。CMA pageblock 不能和普通块合并，这是高阶分配失败的原因之一（[07](./03-07-high-order-and-compaction.md)）。

`vmstat` 里有 `cma_alloc_success` / `cma_alloc_fail`（`mm/vmstat.c:1337-1338`，包在 `CONFIG_CMA` 里）。debugfs 在 `CONFIG_CMA_DEBUGFS` 下看位图。sysfs 的成功/失败页数在 `CONFIG_CMA_SYSFS` 下，由 `cma_sysfs_account_success_pages` / `cma_sysfs_account_fail_pages`（`mm/cma.h:45-46`）累加。
